# Benefits to stick to VIM/NVIM

## Speed and Efficiency

Once learned, vim allows rapid text manipulation with keyboard strike, enable
fast coding and editing compare to mouse-based editor.

## Customization

Extensive configurations options allow users to customize VIM with specific
needs and workflow.

## Portability

As a standard UNIX tool, available on almost any operating system.

## Important aspects in integrated workflow

### telescope and fuzzy finder

#### Primary components

- 1 Picker: central UI dedicated to varying use cases
  (finding files, grepping, diagnostics, etc.)
  see :h telescope.builtin
- 2 Finder: pipe or interactively generates results to pick over
- 3 Prompt: user input that triggers the finder which sorts results
  in order into the entry manager
- 4 Results: listed entries scored by sorter from finder results
- 5 Previewer: preview of context of selected entry
  see :h telescope.previewers

#### Mode concept

Telescope has normal, insert modes just as vim. In insert mode, input goes into
prompt directly, finder generates search results at the same time. In normal mode,
it's possible to navigate the results list with VIM keys (`j/k/H/M/L/gg/G`).

#### Mapping

### Quick Fix

- Location List
  A location list is a window-local quickfix list.
  A location list is associated with a window and each window can have a
  separate location list. A location list can be associated with only one
  window. The location list is independent of the quickfix list.
  When a window with a location list is split, the new window gets a copy of the
  location list. When there are no longer any references to a location list,
  the location list is destroyed.
  The location list commands are similar to the quickfix commands, replacing the
  'c' prefix in the quickfix command with 'l'.

  - command to generate location list
    `:lvimgrep`, `:lgrep`, `:lhelpgrep`, `:lmake`
  - location list command
    `:lopen`,`:lnext`,`lprev`,`lfirst`,`llast`

- Quick Fix List
  Quick fix list is global to vim session. Each quickfix list has a unique
  identifier called the quickfix ID and this number will not change within a Vim
  session.

  - command to generate quick fix list
    `:vimgrep`, `:grep`, `:helpgrep`, `:make`
    `:vim[grep] /patten/ *`
  - quick fix list command
    `:copen`,`:cnext`,`cprev`,`cc`,`cfirst`

  - telescope search with `CTRL+q`, put search results into quick fix list

  - Maps for navigation
    `vim.keymap.set('n', '<M-j>', '<cmd>cnext<cr>', { desc = '' })`
    `vim.keymap.set('n', '<M-k>', '<cmd>cprev<cr>', { desc = '' })`

  - `:cdo`

# [Register and MACRO](https://www.brianstorti.com/vim-registers/)

- `:reg ` to list all registers and contents

```command
:reg " . %
Type Name Content
  l  ""   ^J
  c  ".
  c  "%   2024-10-23-vim.markdown
```

- Visit register in insert/command mode with `<CTRL-r>`
  Add register name after `<CTRL-r>` will paste content of the register.

- Normal named registers
  `a b c d e ... z` or `A b C D E ... Z`

- Unnamed register `"`
  Any text delete (`d c s x`) or copy `y` saved in unnamed register, which could
  paste with `p`. `p` is same as `""p`. `""` reference unnamed register.
  `"ap` paste register `a`.
  `"bp` paste register `b`.

- Numbered register `0 1 ... 9`
  `"0` will always have the content of the latest yank.
  Others will have last 9 deleted text, being `"1` the newest.
  `"9` the oldest.
  We yank some text, then delete some other, and when we try to paste the yanked
  text, it’s not there anymore, as unnamed register content replaced by
  deletion. Use `"0p` find the latest yank!

- Read only register : `. % : and #`
  Last insert context `.`
  Current file path `%`
  Latest command `:`. Use `@:` to execute the command again.

- Expression register `=`

- MACRO

  `n mode`: `q + register` to start recording a set of actions, another `q` to stop
  `n mode`: `@ + register` to preform the execution

- Secret `let` command
  `let @+=@%` copy current file path to clipboard
  let reference unnamed plus register have the same effect of reference `%`
  `let @+=@w`
  let reference unnamed plus register have the same effect of reference `w`.
  Copy macro recorded in register `w` to clipboard, in other nvim instance,
  `@+` will repeat actions in `w`.

# tips easy to forget

- `:r !command`
  insert command execution results into current buffer

- `:%! grep xxx`
  grep xxx results in current buffer

- Undo/redo
  `u`, undo the edit. (undo history related)
  `<C-r>` redo the changes which were undone (undo history related)
  `U` reverse all changes in last modified line, the reverse itself could be
  reverted by `u`

- binary file
  `vim -b file`
  `%!xxd` convert to hex display
  `%!xxd -r` convert back

- `<C-r>`
  reference registers in c, i mode

  CTRL-F the Filename under the cursor
  CTRL-P the Filename under the cursor, expanded with 'path'
  CTRL-W the Word under the cursor
  CTRL-A the WORD under the cursor
  CTRL-L the line under the cursor
